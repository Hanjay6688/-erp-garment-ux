# Pabrik privat: pemulihan fixture yang benar

Kandidat terdahulu mengambil `current-factory-finance-qualification/fixture.py`
dari commit daab, bukan file `current-factory-finance-runtime-qualification/fixture.py`
yang benar-benar dijalankan. Kedua file ada pada commit sama. Karena itu klaim
"fixture date-corrected" sebelumnya salah. Original c17b56ed mempertahankan
penolakan BF_HISTORY sebelum kasus analisis; jangan menulis pabrik lulus.

Kandidat ini memakai byte persis fixture runtime daab yang telah membentuk
1.200 SKU × 3 ukuran melalui penulis Native. Penjualan historis dicatat dahulu;
kelompok SKU baru dibuat pada waktu sekarang per batch. Sembilan tabel posted
dibandingkan seluruh barisnya sebelum dan sesudah membership. Tidak ada jam,
tanggal transaksi, penjaga produk, rumus, batas waktu, atau tabel yang ditambal.

Runner/probe privat persis pendahulu: 24 metrik resmi, signature terpisah,
UNKNOWN, semua target/halaman, uang/stok/HPP, jadwal menit asli tanpa manual tick,
300 detik, unit 8 detik dan pemulihan 22 katalog/baris/sequence tetap sama.
Fixture benar menambah dua assertion penjagaan sejarah (total 65).

Prasyarat: enam suite performa baseline PASS, Native45 aktual PASS, Original daab
INCOMPLETE yang membuktikan fixture sudah PASS, dan Original c17 INCOMPLETE yang
membuktikan salah sumber. Bukti komponen/baseline bukan kelulusan pabrik privat.
Hasil server kandidat baru wajib diperiksa tersendiri. Default, produksi,
audit independen dan cabang B tetap belum diubah.
