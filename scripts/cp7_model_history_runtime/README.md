# Immutable single-product history — opt-in runtime candidate

Two authenticated facades capture/read one explicit physical-root and size over
closed WIB days (at most366). The existing four operational permissions are
checked by the actual Native access helper. Capture takes the global envelope,
then a distinct method/actor/UUID lock and rechecks access after each wait.
The exact original JSON payload binds replay. A separate immutable RLS table
stores source, actual server capture time and the original calculated history.

New captures recheck full source identity and runtime engine before insertion
and again through the reader before returning. Any refusal rolls back the whole
call. Reading checks current actor/access/source twice and returns the old
history verbatim alongside a separately named current guard. Changed physical
rows, target identity, source availability or runtime engine retire the archive;
known incompleteness is never turned into zero. Unexpected errors propagate.
No historical knowledge time is invented and no forecast is activated.

Five private functions, two facades, one private table; no existing replacement,
Native ERP DML, old global-history/model change or default installation. The
opt-in installer verifies exact22 catalog and dependencies. Its savepoint-atomic
pre-use inverse refuses retained runs or external callers; after-use restoration
requires a separately qualified composed backup/restore.

Local11PASS exercises actual SQL/source/history/access body on controlled ERP
tables and auth primitives. Counter-driven interleavings are explicitly local;
they are not actual concurrent backends or Auth. Exact Native catalog/runtime,
two-session races, Auth HTTP, browser/client and model-dataset/target integration
remain open. Neither this source nor these local tests qualify full OW11.
