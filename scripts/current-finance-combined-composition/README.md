# Closed combined finance composition — A

VENI. VIDI. VICI. ERP. Reliable data adalah dewa.
Keuangan termasuk laporan, stok, dan HPP adalah raja.

This is the next isolated integration of the report/book consistency repair and
one official financial check per report. It is not the candidate currently
running on GitHub. Prerequisites stay closed until all seven diagnostics,
Native20, actual cron and complete restorations have exact accepted Original
and package bytes. The first NULL-snapshot counterexample remains INCOMPLETE.

Even an accepted prerequisite proves the changes separately. This composition
must have its own unchanged financial/BusinessReport regressions, concurrent
source and access tests, actual scheduler, factory completion, UI/transport and
full restoration evidence before any default-adoption decision. It is not an
upgrade of existing nonempty captures. No B files, ordinary timeout, source
chunk size, posted history or Native writer is changed.

The closed qualification entry point is `qualification_probe.py`. Seven
separately restored groups exercise the combined installation: unchanged
child-transaction refusal, assigned-XID/NULL-snapshot refusal and recovery,
Native20, independent canonical signatures, current public minute cron,
three whole-report comparisons, and current public factory1200x3 minute cron.
The factory runner retains all 36 assertions of the original factory runner;
only its current public finance adapter, catalog provider and paths change.
The outer probe retains all nine full-restoration assertions.

Retained consistency operations replace only their temporary installation
callback with verification of the actual combined installation. Their business
oracles are unchanged. Report comparisons temporarily restore four exact
accepted reader bodies inside a rolled-back diagnostic transaction; this is
not the product inverse and never erases posted or capture data. Comparisons
omit only captured_at and require one official check plus one canonical scan
on the combined reader, no table writes and the entire report unchanged.

Every group starts from a complete restored unused database. Portable catalog
spellings are compared without changing the original raw installation seal.
The first committed group must prove the actual combined USED guard; later
raw-catalog refusals are recorded separately. Full restore remains mandatory
even when an inverse assertion fails. Browser/Auth and final performance
acceptance remain separate. A closed execution workflow is prepared; its
execution branch has not been created and no new runtime result is claimed.

The workflow preserves the accepted source and restore steps. Before ERP
tests it allows four bounded startup attempts, uses ECR only on attempt two,
and returns to GHCR on attempts three/four. This addresses actual faa's
transient GHCR limit followed by repeated ECR quota failures. Every complete
attempt log and its digest is retained. Image tags, ordinary statement limits
and business tests are unchanged. Artifact names include the run attempt so
an earlier retained artifact does not need to be overwritten.

Source preparation now uses one full-history auditor checkout and 13 detached
worktrees at the exact original frozen commits. Every commit is preflighted
before creating any source directory; every resulting HEAD, tree, top-level
path and clean status is verified. A missing commit fails before DB startup.
Mutable refs and outside paths are rejected. No alternate source or network
fetch is performed by the materializer. Three real Git fixture tests cover
distinct commits, shared history, refusal before partial creation and invalid
refs/paths. This reduces repeated repository transfers; application latency
and actual CI preparation time still require measurement.

Each paired report also retains the live declarations of all functions seen
by track_functions, including volatility, authority and exact definitions.
An observed volatile financial reader prevents this group from passing and
remains available for diagnosis. The unchanged void Native access guard is
identified separately. This is evidence for the observed paths, not a complete
transitive call graph or independent audit. Static source searches alone do
not certify the installed function declarations.
