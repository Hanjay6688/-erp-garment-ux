# Frozen analysis readers — preparation only

The current analog reader requires v1 and reads compiled inputs directly from
jobs.reference. V2 deliberately leaves that reference immutable and PENDING.
This separate v2 reader uses the finished job's bound immutable cache, or, after
the existing K3 cleanup, recompiles solely from the retained frozen capsule.
It never recaptures live facts, writes a cache, rewrites a reference, changes
the old reader or substitutes a zero/invented completed status.

The admitted reader supplies every current-access/actor/access-epoch/page-set/
clock/query/source binding guard. Candidate selection math is unchanged. The
new response has explicit v3 and bounded-request/reference-v2 contracts. Current
producer identity is checked before compiling and again before returning;
current access is rechecked after work. The new namespace is outside the unit
producer definition set, so adding this reader does not reinterpret old hashes.

Two private functions, one authenticated public facade, one schema, no tables
or old replacements. The prepared installer checks all22catalog groups and
existing function dependencies, owner/ACL/config, source bytes and pre-use
usage. Inverse removal is savepoint atomic and refuses external dependents.

No Native, Auth, full-scale read latency, after-K3 parity or actual frontend
qualification yet. A separate opt-in F05 qualification route is prepared; no default installer or public UI adopts this package.
It must qualify before the v2 quantity screen exposes analog comparison.

The explicit frontend reader lives outside the application graph. The shared
parser accepts v3 only with an explicit FROZEN_V2 context and both v2 contracts;
it rejects mixed-method pages and prevents either RPC from receiving the other
method's context. Existing v1/v2 parsing remains covered. Six controlled PG18
checks and 77 frontend checks pass; these are not Native17 or browser evidence.

The separate prepared Native4 provider covers exact catalog/inverse, physical
size and available-zero versus unknown history, cached/K3/post immutable reads,
current access/retention/old-method refusals, and first-page parity for the three
physical sizes in the 1200-SKU fixture. Its closed F05 route and Native4 workflow pass local admission checks; neither has run yet.
The existing analog CONFIRM command still calls the old reader and requires its
own explicit versioned adapter before this method can expose choice saving.
Existing saved choices may be explained by the reader; this preparation does
not qualify new choice writes, a complete quantity UI, or factory-wide SLA.
