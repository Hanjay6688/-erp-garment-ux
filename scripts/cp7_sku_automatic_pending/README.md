# Automatic rework/redye with provisional PO costs

Automatic completion previously reached the strict manual SKU price gate and
failed when genuine PO costs were numeric but still estimated or incomplete.
This successor binds provisional pricing to the exact Native rework result.

The private context binds backend, transaction, Native request, server-created
conversion, completed rework, target configuration, BS/PO lineage, real GOOD
lot, quantity, warehouse and physical timestamp. It exists before the Native
helper computes its expected source revision. The unchanged Native posting
and inverse guards still execute. A successful command retains immutable
admission proof and removes its own temporary context.

Automatic source and target pools keep the complete SKU moving average and
include reservations. Every numeric component must exist. Pending non-PO
components and absent numeric costs remain refused. Provisional values retain
an explicit pending label in the private original preview. Ordinary manual
reply fields and unknown-cost refusal remain unchanged. Private factories
and history have no direct PUBLIC, anon, authenticated or service_role grants.

The isolated PG17.5 model passes 18 focused controls, plus two fixture/source
preconditions. It executes the exact BE automatic post/inverse, physical
movement and conversion functions, source-price propagation, Native PO and
non-PO book readers, and PO book assertions. A real selected lot value of 50
transfers economic value 35 from a two-piece pool worth 70. Replays, three
pending states in both modes, current-price inverse, late cost events and
their dependency refusal, request/scope boundaries, late failure rollback,
zero GOOD and ordinary manual behavior are checked. All modeled table rows
return to their original state after each case.

The model begins at a **modeled already-completed rework/GOOD boundary**. It
does not execute the upstream completion command or actual Auth. The PO GL
sync is an explicit independent physical-value model limited to unsold PO
pieces; the real Native PO target/book assertion checks it. Document
cancellation is a modeled legal postcondition followed by the exact Native
source reconciliation. These limitations do not grant actual ERP acceptance.

`prepared_product.derive` composes the unchanged money parent, private
accounting reader and automatic successor into one definition set. All eight
overlays and the private DDL match the executed model. The 44 original money
product files remain unchanged.

`composition` now owns a separate incremental stage over the exact frozen
money composition. It installs two private tables and ten private helpers,
and replaces exactly nine existing definitions. The accounting scope is an
existing replacement, rather than a duplicate table/helper installation.
All eight automatic overlays and the private SQL remain byte-exact to the
executed business model. The full money parent is not installed twice.

The isolated PG17 DDL capture installs and explicitly removes this delta as
an ordinary `postgres` owner (`rolsuper=false`). A privileged observer reads
the system catalogue outside the owner scope, as the owning composition
does. Existing parent schema identities are model setup. All 22 catalogue
groups restore exactly; all existing function metadata and ACLs remain
unchanged. Sixteen metadata counterexamples and seven forged profile
authority changes refuse. The actual inverse function also refuses changed
rows or sequence state before any DDL. These controls do not qualify the
full parent installation or actual ERP permissions.

No workflow is activated. Full Native completion, Auth, races, browser,
current catalogue, permission and full backup/restore qualification remain
required. The unchanged Native completion/reversal call order was checked
against the retained current sources; no upstream business command was run
in that source check.

First failures are preserved: the old test balance provider counted PO-tagged
lines as non-PO (corrected using the exact Native book reader), then a new
PL/pgSQL conditional failed compilation. New function validation now runs
before the focused business cases. No monetary tolerance or financial guard
was weakened.
