# Current SKU value display on the completed B theme

This prepared UI successor keeps 74 presentation derivations byte-for-byte from
`62124cd356c33927df7a871f50642e94f1a9580a` and imports exactly five reader/client
files from SKU candidate `fea75841e26645f1892d880905231625b47e3065`. It accepts
the closed SKU pool descriptor only for GRADE_A, retains the older lot contract,
labels the current card cost as HPP SKU, and preserves operations-only responses
without monetary fields. SQL, authority, transaction writes and recovery are
unchanged. The financial candidate's actual qualification remains separate.

The source guard compares every unaffected source file with the completed theme
and every reader file with its pinned donor bytes. The 32 existing reader/DOM
controls and build/source/access/CSS checks run before visual capture.

`capture.test.tsx` mounts the actual connected FG page with explicit synthetic
read/auth providers. It uses the real parser and pending-recovery hook, while
omitting the unrelated demand panel. It captures seven states: known SKU cost,
unknown cost, empty stock, loading, read error, pending transaction and operations
without finance permission. No business write or live service call is allowed.

FG CSS. It measures 320/390/768/1440 px, full-page overflow, visible control
width and text contrast; known-cost details are also expanded. The 32 screenshots
are an isolated markup/CSS test, not authenticated ERP or full App acceptance.
The dedicated CI owns no database and cannot contend with financial qualification.
No production deployment or unified runtime gate is enabled by these checks.
