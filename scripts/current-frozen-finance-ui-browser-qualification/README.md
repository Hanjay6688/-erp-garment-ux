# Pengujian layar keuangan A pada komposisi publik lengkap

Native52 dan Auth3/races7 publik yang aktual PASS wajib diverifikasi sebelum
SOURCE diikat. Setiap kasus mendapat clone penuh terpisah: desktop membuktikan
angka READY dari baseline resmi tanpa membuat pekerjaan produksi tambahan;
HP memakai fixture posted yang Native52 buktikan BLOCKED, sehingga semua angka
ditahan dan UNKNOWN tidak menjadi nol. Jika baseline positif belum READY,
kasus gagal dengan rincian laporan; tidak ada perubahan fakta untuk memaksa lulus.

Kedua kasus memakai AuthProvider/AuthGate/PostgREST asli, dua RPC A, caller B
byte-exact, UUID tersimpan, progress keuangan terpisah, seluruh 24 metrik dan
signature buku. Kasus desktop kehilangan delivery respons asli lalu reload;
HP mencabut finance.reports.view setelah capture selesai. Capture dikerjakan
oleh helper SQL privat terpisah, bukan diklaim cron atau HTTP. Semua halaman,
riwayat, stok/uang/HPP, ACL, sesi, full22/rows/sequences/CP6/advisor dipertahankan.

Kasus analog/cutting B terbaru dan skala pabrik tidak termasuk kredit suite ini.
Tidak ada default adoption, production_go atau penerimaan independen.
