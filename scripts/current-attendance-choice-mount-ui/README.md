## Closed reader wire

Affected pool objects gain exactly one optional object. Unaffected ordinary pool
wire objects remain unchanged; neither explicit null nor both objects are accepted.

| Object | Exact keys | Meaning |
|---|---|---|
| attendance_choice | domain, decision_id, allocation_id, source_period_start, source_period_end, output_period_start, output_period_end, output_period_closed | Permanent ownership, ACTIVE or CANCELLED, actions empty. IDs do not assert the old decision is still current. |

Both domains are `ATTENDANCE_PERIOD_CHOICE`. Source dates equal the old pool header.
Output starts strictly after source end. `period_closed` keeps its source-P1 meaning;
the independent output flag must agree with workspace `closed_through`. A held
preview uses the existing BLOCKED/no-figures shape, null token/manifest, empty `pos`,
`can_create=false`, and `{code:'CP7_S03_PERIOD_HELD',message:...}`. Missing/foreign or
malformed metadata is refused, never treated as an ordinary actionable pool.

Owner can open a fresh source-period workspace, including with view-only rights.

added. The route transfers only source dates. It transfers no old decision intent,
pool ID, 32-character pool review token, or UUID into the fresh 64-character S03 review.
Opening the same source again increments its context key. Current actor/permissions
remount the workspace. Global pending recovery keeps its persisted domain/envelope.

Choice commits refresh old pool plus recost/finish; old pool commits refresh choice
plus recost/finish. Other HPP commits refresh both readers. Each attendance writer
excludes its own commit from its refresh input, preserving its response fence.
