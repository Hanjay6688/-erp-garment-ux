### Phase D findings and integrator decisions (7 Oct 2026)

Measured (LOCAL_PG16_DEV unless stated; full notes and logs of the phase D prototype are summarised here):
- Real Originals are 45–50 KB per target (retained Native Originals of 3–14 targets) and 42 KB per target on CI at 100 targets; `timeline` is 77–78 % (about 11 items per target, one per horizon day, about 3.2 KB each because real refs are UUIDs).
- One jsonb `runs.result` at 5,000 real-shaped targets: 218.9 MB of text, **237.9 MB of jsonb = 88.6 % of PostgreSQL's hard jsonb limit** (a 251 MB text is refused with 54000); parse + insert 7.8–13.5 s locally (about 5–9 s on CI-class hardware). A single jsonb result is therefore not a supportable home for a 5,000-target run.
- Every whole reader (`serve`, manifest, reminders' `access_now`, archives, reports, fabric workspace, plan draft, AI handoff) would build or detoast the whole ≈210 MB result.

Decisions taken as integrator (no earlier owner decision reopened; new contracts listed for auditor acceptance):
1. **Storage C:** a staged run keeps a header (all non-per-target fields) plus pages bound to the run and to the semantic hash; it is never stored as one jsonb result. It lives apart from `cp7_analysis_native.runs`, so every existing whole reader finds no such run and refuses (fail closed by construction), instead of mistaking a header for a whole result.
2. **Byte-adaptive pages:** a page is cut at a target boundary by size (≤ 8,000,000 bytes, the existing segment body bound), not by a fixed 500 targets: at the real 45 KB per target a fixed 500-target page (≈22.7 MB) would be refused.
3. **Semantic hash unchanged:** one sha256 over the whole analysis text, computed in its own unit.
4. New contracts `cp7.native-analysis-pages.v1`, `-header.v1`, `-page.v1`, `-page-read.v1` and the refusal `CP7_ANALYSIS_RUN_PAGED` are additions; auditor acceptance pending.

Open (owner priority needed, stated as unavailable in the UI until then): reminders/attention, reports, fabric workspace, plan draft and AI handoff on a staged run each need a target-range or target-key reader.

## 0. Binding owner decisions (quoted) and the rules derived from them

> "5.000 target: setuju jadikan kapasitas yang didukung. Boleh lewat pekerjaan latar dan pemrosesan bertahap, dengan data acuan yang konsisten. Harus selesai seluruhnya, tanpa pemotongan data diam-diam. Menaikkan angka batas saja belum cukup."

> "Latensi: pekerjaan berat boleh berjalan di latar belakang sebagai pengecualian yang dicatat. Layar tetap responsif, status/progres nyata, aman ditinggal dan dibuka kembali. Jangan menandai target selesai 3 detik sebagai tercapai kalau memang belum."

Rules: (1) every stage call stays under the unchanged 8 s statement limit; (2) work is split into units that persist intermediate state, one ordinary request each; (3) all units read ONE consistent reference; a changed source is reported, never mixed; (4) all 5,000 targets, no sampling/truncation, a partial result is never shown as complete; (5) progress is real, persisted, survives reload; a job left alone resumes or reports its true state; (6) single-call caps may become per-unit bounds, never simply raised; remaining caps stay declared and refuse loudly; (7) byte-identical to the single-call path where both run, proven by a parity test; (8) no refusal/oracle loosened.

## 3. Snapshot (reference) and consistency

- The job stores **one** copy of the captured source (`cp7_analysis_stage.snapshots.facts`) and its fingerprint (`cp7_analysis_native.fingerprint`, = the run's `dependency_hash`). Every unit reads only that copy and earlier units' outputs; all those rows are insert-only (`cp7_private.immutable_run` triggers). A job therefore cannot mix source versions; this is by construction, not by checking.
- The capture itself is the one place where consistency must be earned. In this architecture (one request = one transaction, no session that outlives a request) the only exact method is **one statement snapshot**. Proposal: CAPTURE_OP stays one statement; its product bound becomes the declared capacity (5,000) only if CI shows the one-statement capture at 5,000 ≤ 2 s on the slower runner (≤25 % of 8 s). Unmeasured: today's source query stops at 1,001 products.
- If it does not fit, or for CAPTURE_FIN: capture in parts, each part storing a fingerprint over `(row id, xmin, row content)`; after the last part, a verification pass re-reads every part's fingerprint **in capture order**; DONE only if all are equal, otherwise the job state is `SOURCE_CHANGED` and capture restarts (bounded attempts, then `CP7_ANALYSIS_SOURCE_UNSTABLE`). This detects every change still visible at verification and every update/re-insert (new xmin). It cannot see a row version both created and deleted between a part's capture and its verification; two such versions in different parts can yield facts that match no single instant. Closing that needs a writer-maintained monotone change marker (touches every ERP writer — owner/product decision), or tables proven insert-only (journals: to be verified).
- Freshness after DONE is reported, not forced: the job finishes on its reference and the manifest reports `UNCHANGED`/`ARCHIVED_STALE`. Auto-restart on every change would never finish on a selling day. At 5,000 the existing manifest recomputes the full source in one call (over budget) — the freshness check must use the same part fingerprints (open).

## 5. Persisted tables, progress, failure and resume (prototype schema `cp7_analysis_stage`)

- `jobs` (actor, request, query, fixed `run_id`, access at capture, reference hash, state RUNNING/DONE/FAILED, `unit_count`, `units_done`, `plan_final`, `targets_total`, `unit_attempts`, failure unit/sqlstate/code, timestamps); `snapshots` (the reference); `units` (the plan: kind, chunk, lo, hi — fixed by NET_PREP: 2 units before, all after); `outputs` (one per finished unit, with server ms); `target_rows` (per-target intermediates: BASE/STOCK/HIST/NET1/NETROW/FAB); `pair_rows`, `pair_lists` (verdicts per position, results per target key with the eligible index); `fragments` (per-chunk text of each per-target array); `texts` (analysis and document text). All except `jobs` are insert-only; RLS deny-all, owner `cp7_capture`, like `analysis-jobs.sql`.
- `step(job)`: locks the job row `FOR UPDATE SKIP LOCKED` (a second caller gets `worker_active:true` and runs nothing), runs unit `units_done`, inserts its output, advances. A unit stopped by the statement limit (57014) is retried by the next call from the same immutable inputs; 3 stops ⇒ `FAILED / CP7_ANALYSIS_STAGE_STOPPED`. Any other refusal ⇒ `FAILED` with the single path's code (`CP7_*` message) or `CP7_ANALYSIS_STAGE_ERROR` + SQLSTATE; retrying a fixed reference would refuse identically.
- `status(job)` is read from these rows: stage name, stage k of n, units done/total, targets done in the current per-target stage / total, reference time and hash, last progress time, attempts, failure, and `run_id` only when DONE. A partial job never exposes a result.
- Driver: the prototype is client-driven (the page calls `step` in a loop, each call one request; on reload it reads `status` and continues). A job left alone does **not** advance but reports its true state ("paused at unit k/n since T") and resumes from unit k when any session of the actor calls `step`. A real server-side driver (pg_cron / scheduled function) must run units with an explicit `statement_timeout='8s'` and re-check the actor's current access per unit (no `auth.uid()` there) — infra/product decision, open.

## 6. Final Original, fingerprint and parity

- ANA_META builds the analysis with the per-target arrays replaced by sentinels (`P19-STAGED-<job uuid>-<field>`, unique per job) and applies the finance overlay (`finance_apply`). ANA_TEXT renders that skeleton (jsonb text is canonical), replaces each sentinel by the chunk fragments joined with `", "`, computes `semantic_hash = sha256(text)` exactly as build does, and stores the text. RUN_INSERT parses it into `runs.result`; DOC_RENDER renders `cp7_analysis_jobs.original()` with the analysis sentinel and substitutes the text; DOC_SEGMENTS writes the same document/segment rows as `store()` (2,000,000 characters, UTF8 sizes, hashes) with a linear cut. The existing manifest/segment readers serve the staged run unchanged.
- Parity (`tests/cp7/families/f05-staged-analysis.test.ts`, 4/4 pass, logs 16/24/26):

## 8. Open (not done, in order of risk)

1. **Client cannot hold the 5,000-target Original** (64 MB cap; real ≈210 MB). Needs reading the immutable Original by target range (server-sliced pages under the same run hash and segment hashes) and a UI that never presents a page as the whole. Frontend not touched.
2. **Byte-proportional global units**: ANA_TEXT, RUN_INSERT, DOC_RENDER ≈2 s each at 65 MB locally ⇒ ≈7 s at the real 210 MB, ≈14 s on CI. The frozen `semantic_hash` (one sha256 over the whole analysis text) keeps one ≥210 MB unit; `runs.result` as one jsonb (parse + TOAST) does not fit — a staged run needs a text-backed result (contract change for `runs`, its readers: archive, publications, reminder conditions) or a contract decision on the hash.

## 10. Product contracts for the staged path (phase C2; integrator decision, auditor acceptance pending)

Binding for the product move. Nothing here changes the single path (`cp7_analysis_native.runs`, `serve`, `capture`, jobs, manifest, segments, their contracts and caps).

**Where a staged run lives.** Schema `cp7_analysis_stage` (owner `cp7_capture`, no USAGE for `public/anon/authenticated/service_role`). A staged run is the job row (`run_id` fixed at request) plus its header and pages; it is **never** inserted into `cp7_analysis_native.runs`, so every existing whole reader (serve, manifest, archives, reminders, reports, fabric workspace, plan draft) finds no such run and refuses as for an unknown run. All tables: RLS deny-all policy, no grants, owner `cp7_capture`; reference, units, outputs and every intermediate row immutable (`cp7_private.immutable_run`), except the job row's progress columns.

**Units.** Phase B scenario units, phase A netting/allocation units, `FABRIC_PLAN`, `ANA_TARGETS` (fragments per chunk **and** the UTF-8 size of every target's items per array), `ANA_META` (header skeleton), `PAGES` × k, `PAGE_INDEX`. No unit builds the whole analysis text or the whole Original (`ANA_TEXT`, `RUN_INSERT`, `DOC_RENDER`, `DOC_SEGMENTS` are not part of the product path). Per-unit and per-job bounds as in phase B. Every unit under the unchanged 8 s.

**Pages are byte-adaptive.** A page is a contiguous range of targets in the job's loop order whose page body is ≤ 8,000,000 UTF-8 bytes (the existing segment body bound); a single target whose items exceed it fails the job (`CP7_ANALYSIS_PAGE_BODY_LIMIT`), never cut. The page index is written last; a job without it exposes no page.

**Identity.** `identity_hash = sha256(header_sha256 || E'\n' || string_agg(page_sha256, E'\n' order by index))` (hex). The single path's `semantic_hash` (one sha256 over the whole analysis text) is not computed for staged runs; tests prove that header + pages reassemble, byte for byte, the analysis text and the Original of the single build on the same reference, and recompute its `semantic_hash` from the reassembled text.

**Public RPCs** (all `authenticated` only, `SECURITY DEFINER`, owner `cp7_capture`, `search_path=''`, read committed required where the single job requires it):

| RPC | Does | Returns |
|---|---|---|
| `erp_cp7_request_staged_analysis_v1(p_query jsonb, p_request uuid)` | same request UUID + same query → same job; a UUID the actor's ordinary capture or analysis job owns → `CP7_ANALYSIS_REQUEST_CHANGED`; else captures the reference in ONE statement: `cp7_analysis_native.source_within(job_targets, job_matching_products)` + `financial_source:null`, `financial_capture:'DEFERRED'` (operational path; the owner report and the books are never read), access re-read after the capture | job status |
| `erp_cp7_step_staged_analysis_v1(p_request uuid)` | re-reads the actor's access; different from the access at capture → job `FAILED` `CP7_ANALYSIS_ACCESS_CHANGED`; else runs the next unit (`FOR UPDATE SKIP LOCKED`: a concurrent caller runs nothing and gets `worker_active:true`); statement-limit stop retried up to 3 times, then `FAILED CP7_ANALYSIS_STAGE_STOPPED`; any other refusal `FAILED` with the single path's code, SQLSTATE and message | job status |
| `erp_cp7_get_staged_analysis_v1(p_request uuid)` | status from rows; never runs a unit | job status |

**Job status** `cp7.native-analysis-staged-job.v1`: `request_id`, `state` (`RUNNING`/`DONE`/`FAILED`), `stage`, `stage_index`, `stage_count`, `units_done`, `unit_count`, `plan_final`, `targets_total`, `targets_done_in_stage`, `reference {captured_at, source_hash}`, `last_progress_at`, `unit_attempts`, `run_id` (DONE only), `failure {unit, sqlstate, code}` (FAILED only), `worker_active` (only on a skipped step), `apply_enabled:false`, `production_go:false`.

**Page set** `cp7.native-analysis-pages.v1`: `run_id`, `request_id`, `reference {captured_at, source_hash}`, `access_epoch`, `identity_hash`, `targets_total`, `page_count`, `paged {array: {prefix, items}}`, `totals`, `header {utf8_bytes, sha256, body}`, `pages [{index, target_lo, target_hi, utf8_bytes, sha256, counts}]`, `apply_enabled:false`, `production_go:false`.
**Header** `cp7.native-analysis-header.v1` (the `header.body` string): `run_id`, `request_id`, `query`, `financial_source` (null), `product_labels`, `analysis_header` (the analysis without per-target items and without `semantic_hash`), `paged`, `targets_total`, `page_count`, `apply_enabled:false`, `production_go:false`.
**Page** `cp7.native-analysis-page.v1` (the envelope's `body` string): `run_id`, `request_id`, `index`, `page_count`, `target_lo`, `target_hi`, `targets_total`, `header_sha256`, `counts`, `offsets`, `totals`, `summary`, `items`, `apply_enabled:false`, `production_go:false`.
**Page envelope** `cp7.native-analysis-page-read.v1`: `run_id`, `index`, `page_count`, `target_lo`, `target_hi`, `header_sha256`, `identity_hash`, `utf8_bytes`, `sha256`, `body`.

**Retention.** Intermediate rows (fragments, target/pair rows, outputs) are needed only until `PAGE_INDEX`; a private admin function may remove them for a finished job (no grants; no automatic retention: the value is an owner decision, PENDING_POLICY_VALUE). The reference, header, pages and job row stay.

**Driver.** Client-driven: the page calls step in a loop and resumes after a reload by reading status; a job left alone reports "paused since T" and continues when any session of the actor calls step. A server-side driver is an open infra decision.
